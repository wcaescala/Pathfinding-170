Milestone 1: Proposal & Algorithmic Foundations

The Dragon Age 2 Pathfinding Benchmark Dataset

The Moving AI Dragon Age 2 (DA2) Pathfinding Benchmark provides grid-based maps and pathfinding scenarios sampled from real video game environments. The maps vary significantly in geometry, obstacle density, and navigation complexity — from open city plazas to winding cave labyrinths. Each scenario defines a fixed start coordinate, goal coordinate, and precomputed reference optimal path length, ensuring all six algorithms are evaluated under identical conditions.

Algorithms Compared

Dijkstra's Algorithm

The optimal uninformed baseline. It explores outward uniformly by tracking accumulated cost from the start node, correctly handling varying edge costs (such as √2 diagonal movement) without heuristic direction. Comparing it with heuristic-guided methods quantifies the precise search reduction gained by goal guidance.

Breadth-First Search (BFS)

Explores neighbors level-by-level using a FIFO queue, guaranteeing shortest hop-count paths on unweighted graphs. Because the benchmark charges √2 ≈ 1.414 for diagonal steps versus 1.0 for cardinal steps, standard BFS finds paths with near-optimal length (α ≈ 1.003) but does not strictly guarantee diagonal metric optimality.

Depth-First Search (DFS)

Follows a single search branch as deep as possible before backtracking via a LIFO stack. It provides a baseline for unguided exploration without cost tracking, demonstrating how depth-first traversal impacts execution time, search volume, and severe path suboptimality.

Greedy Best-First Search (GBFS)

Evaluates frontier nodes solely by their octile heuristic distance to the goal h(n), aggressively driving towards the destination. It tests how much search time and node expansions can be saved when past path cost $g(n)$ is ignored, in exchange for a modest path optimality penalty.

A* Search

Combines exact cost-to-come g(n) with an admissible octile distance heuristic h(n) to minimize f(n) = g(n) + h(n). With an admissible and consistent heuristic, A* guarantees optimal paths (α = 1.000) while pruning the search space by up to 17× compared to Dijkstra.

Jump Point Search (JPS)

An algorithmic acceleration of A* designed for uniform-cost grid maps. JPS prunes intermediate nodes along straight and diagonal rays, expanding only "jump points" where obstacles force turning maneuvers. It preserves exact path optimality (α = 1.000) while reducing expanded nodes by another 8× over A*.

Evaluation Metrics

Execution Time (ms)
CPU runtime required to compute a complete path from start to goal coordinates under identical hardware conditions.
Path Length & Suboptimality (α)
The true cost of the reconstructed trajectory divided by the reference optimal cost: α = cost / cost*, where α = 1.000 represents a proven optimal path.
Nodes Explored / Expanded
Total states removed from the priority queue or frontier and evaluated. Reflects raw computational work independent of language runtime overhead.
Success Rate (%)
Percentage of benchmark queries solved within strict safety bounds (100,000 node expansion ceiling and 5.0 s timeout).

Milestone 2 Observations

  • Both uninformed algorithms achieved 100% success across all 16 sampled queries.
  • While BFS yielded near-optimal paths (α ≤ 1.051), its node expansion volume scaled quadratically with distance due to unguided circular frontier growth.
  • DFS exhibited extreme trajectory variance: in open queries it darted toward the target quickly, but frequently produced paths up to 40.9× longer than the geodesic shortest route.

Key Empirical Findings

1. Optimality & Path Quality

A*, Dijkstra, and JPS consistently achieve guaranteed optimal trajectories (α = 1.000). GBFS pays a negligible ~8% optimality penalty (α = 1.078) in exchange for massive speed gains, whereas DFS produces severely suboptimal paths (mean α = 7.659, with outliers exceeding 40×).

2. Drastic Search Effort Reduction

Heuristic guidance dramatically curbs unnecessary exploration. A* expands ~17× fewer nodes than Dijkstra, while JPS expands another 8x fewer nodes than A* (median 6.5 expansions). JPS expansions remain nearly constant even as map path lengths grow.

3. Time vs. Expansion Crossover

Although JPS evaluates the absolute fewest nodes, its ray-scanning jump-point loop in pure Python incurs higher per-node instruction overhead. Consequently, A* remains fastest on short/medium queries, while JPS overtakes A* on long, open trajectories.

4. Environment Sensitivity

DFS degraded substantially in expansive outdoor areas. A* required additional expansions in serpentine cave corridors where euclidean distance underestimates topological distance. Across the entire benchmark, GBFS was the fastest solver in ~70% of scenarios.

Interactive Map & Trajectory Visualizer

To inspect algorithm behavior in real time, the project includes a standalone interactive GUI (gui.py) capable of loading any Dragon Age 2 .map file, executing all 6 algorithms simultaneously, and rendering overlaid colored trajectory ribbons.

Running the Interactive Visualizer Locally

Launch the GUI via terminal from the repository root:

python3 gui.py
  • Map Selection: Choose from 67 real Dragon Age 2 maps (caves, city streets, ruins).
  • Coordinate Controls: Type custom (X, Y) coordinates or click directly on the canvas to set Start and Goal pins.
  • Multi-Path Ribbon Overlay: Compares paths side-by-side with distinct offsets and algorithm signature colors.
  • Live Benchmark Table: Displays runtime (ms), path length, node count, and optimality index for every run.
