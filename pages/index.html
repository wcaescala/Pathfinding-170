Milestone 1: Proposal

Dataset

The Moving AI Dragon Age 2 (DA2) Pathfinding Benchmark provides grid-based maps and pathfinding scenarios taken from a video game. The maps differ in size and obstacle layout, and each scenario gives a fixed start and goal, so every algorithm is compared under the same conditions.

Algorithms compared

Dijkstra's algorithm

The baseline. It finds the shortest path by tracking accumulated cost from the start, handles varying movement costs, and needs no heuristic. Comparing it with heuristic methods shows whether goal-directed search improves efficiency.

Breadth-First Search (BFS)

Explores neighbours level by level, which gives the shortest path when every move costs the same. It is the uninformed-search baseline. Because the benchmark charges more for diagonal moves, standard BFS may not find the optimal path under its rules.

Depth-First Search (DFS)

Follows one path as deep as possible before backtracking. It shows how depth-oriented exploration affects time, search effort and path quality, and it does not guarantee the shortest path.

Greedy Best-First Search (GBFS)

Uses a heuristic to expand the node that looks closest to the goal. It tests whether steering toward the destination cuts time and nodes explored. Since it ignores the cost already paid, it does not guarantee the shortest path.

A* Search

Combines the actual cost so far with a heuristic estimate of the remaining distance. With an admissible heuristic and a correct implementation it finds an optimal path, often exploring far fewer nodes than Dijkstra. The benchmark's reference optimal costs make it easy to judge path quality.

Jump Point Search (JPS)

An A* optimisation for uniform-cost grids. It skips intermediate nodes and expands only "jump points" (turning points). It is included to see whether fewer expansions mean lower time while keeping optimal paths.

Metrics

Execution time (ms)
How long each algorithm takes to find a path from start to goal. Shows which solve scenarios fastest and what optimisations like JPS gain.
Path length (distance)
Total movement cost of the path found, following the benchmark's rules including diagonal cost. Shows whether a route is optimal.
Nodes explored
Nodes expanded during search. Indicates how much work an algorithm does and explains time differences, especially A* vs JPS.
Success rate (%)
Share of scenarios where a valid path is found. Measures reliability across maps and obstacle layouts.

Observations

  • Both algorithms found a path in every one of the 16 scenarios.
  • Execution time and explored-node counts varied from scenario to scenario.
  • The summary gives a basis for comparing BFS and DFS, but more testing is needed to see how consistent the differences are across map sizes and difficulty tiers.
  • The loaders, both algorithms and the evaluation system all work, and the tests processed 16 scenarios into comparative tables. The evaluation plan is in the repository's docs folder.

Milestone 3: Comparison of all six methods

This stage implements every algorithm from scratch along with our own evaluation metrics. Scenarios are stratified from the DA2 benchmark: nine maps, five environments, three size tiers, and short, medium and long query tiers. Each algorithm is scored on execution time, nodes expanded, path suboptimality (α) and success rate under a 5 s / 100,000-node limit. The body of the report says the runs cover about 52 scenarios; its closing note says 54 scenarios with k = 2 (full results are in the repository's /results folder).

Findings

Success and optimality

All algorithms achieved 100% success. A*, Dijkstra and JPS found optimal paths. GBFS paid a modest ~8% optimality penalty for speed, while DFS was heavily suboptimal (median α ≈ 3.7, with outliers up to 49×).

Search effort

Heuristic guidance sharply reduced expansions. A* expanded ~17× fewer nodes than Dijkstra, and JPS ~8× fewer than A*. Unlike the uninformed algorithms, JPS expansions stayed nearly flat as paths grew longer.

Time vs. effort crossover

JPS expanded the fewest nodes, but its line-scanning Python implementation has higher per-expansion overhead. A* is faster on short and medium queries, while JPS is faster on long ones.

Environment sensitivity

DFS struggled in open halls and complex terrain. JPS timing stayed consistent across environments. A* slowed in winding cave corridors, where heuristics help less. Overall, GBFS was fastest in ~70% of scenarios.
